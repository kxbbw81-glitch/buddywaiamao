## 1. 目标

V2.0 第一版不是停留在最小链路，而是按阶段完成一套可上线、可扩展、可审计的外贸 AI 一体化业务平台。

主业务闭环：

```text
目标客户/线索 → AI 预审评分 → 客户建档 → 联系和跟进 → 需求确认 → 产品推荐 → 报价与审批 → 样品 → 样品跟进 → 合同/订单 → 收定金 → 生产与发货 → 外贸单证 → 收尾款 → 复购
```

## 3. 当前阶段启动策略

- 阶段 0：已启动，输出完整审计、架构、数据模型、路线图、部署、报价、AI 治理文档。
- P0/P1：已完成本地角色、主业务链路与正式前端集成验收；生产数据/发布门禁仍独立执行。
- P2：AI 治理、RAG、队列/SSE、PostgreSQL + pgvector 迁移与真实本地测试库 E2E 均已验收；真实模型供应商接入仍须在密钥、模型和费用上限授权后单独实施。
- P3：工程化基础已完成本地验收（PWA/移动端、CI、只读运维状态、本地性能基线、备份恢复演练）；其余能力按下列完整工作包继续，不以“最小链路”替代计划版本。
- 只有经过当前里程碑审核后，才进入下一阶段实现。
- 不做 UI 视觉微调、非阻断性能优化、批量脚本扩展、部署或 Git 写操作。

### 3.1 P3 完整执行顺序与固定边界

| 顺序 | 工作包 | 复用基础 | 完成定义 | 明确不做 |
| --- | --- | --- | --- | --- |
| P3-A | 工程化运行底座 | PWA、Next 前端、CI、`ops-routes`、PostgreSQL/Redis E2E、备份脚本 | 真实设备验收、发布前性能/慢查询取证、备份告警接入 | 不自动部署、不在代码中保存密钥 |
| P3-B | 社媒获客助手 | Lead/Inquiry、PII 指纹去重、`IntegrationConnection`、Webhook 台账、AI Capability/ToolCall 审计 | 社媒账号、选题/素材/内容日历、草稿、人工审核、意图标签、转线索建议与 UTM/活动归因均可追溯 | 不爬取未授权数据、不群发、不自动发布/私信/评论 |
| P3-C | 邮件与渠道草稿 | 沟通时间线、通知、连接器台账、人工确认规则 | 邮件/EDM 草稿、审核、结果回填与渠道降级导出；外部渠道不可用时不阻断手工业务 | 不自建邮件服务器、不执行未确认的外部发送 |
| P3-D | 数据分析与预警 | Dashboard、业务闭环数据、RAG/AI 审计和角色权限 | 经营快照、客户流失预警、归因分析、受限只读 NL2SQL、自动报告、销售预测的最小评测与权限验收 | 不越权查询、不将 PII 送往未授权模型 |
| P3-E | 多语言聊天与发布门禁 | 已有 AI Gateway、Prompt/评测/成本策略、队列/SSE | 多语言草稿/人工审核、真实模型受控验收、真实渠道授权验收、灰度/回滚/监控证据 | 不绕过模型、渠道、生产或密钥授权 |

每个工作包固定采用同一节奏：主线只实现该工作包；审核只读给出 PASS / CONDITIONAL-PASS / BLOCKED；性能/QA 仅验证该工作包的门禁。非阻断 UI 微调必须另建专门任务，不得改变主线目标。

### 3.2 本期范围确认（2026-08-26）

- AI 供应商、模型选择、云端处理和费用限额：本期不接入；保留现有本地草稿、能力契约、审计和人工确认边界，不发送业务数据至云端。
- 邮件、社媒、B2B、物流：本期仅保留合规接口、连接器台账、草稿/人工确认/结果回填与手工降级；不配置官方账号、不保存凭据、不执行真实外部动作。
- 因此，P3 的本地交付标准为“接口已留、业务人工流程可用、外部副作用为零”；真实模型和渠道接入将作为未来独立授权工单。
