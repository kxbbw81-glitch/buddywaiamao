# NexFab CRM 正式前端 全量审核与修复报告（2026-08-30）

> 审核对象：发布基线仓库的正式前端（Next.js 15 App Router + React 19 + Tailwind，28 个 ts/tsx 文件）
> 修复副本（本文件夹，原目录零改动）：`nexfab-v2-frontend-audit-fixed-20260830`
> 每处修改均含 `// 修复说明：[问题类型]，原因：[具体原因]` 注释。

## 一、审核总览

- **整体风险等级**：中危。XSS 面、token 存储面干净（全程 HttpOnly cookie + `credentials:'include'`，无 localStorage 存 token，无 `dangerouslySetInnerHTML`）；核心风险集中在 **BFF 代理层暴露面过大** 与 **修复过程中发现的配对/可移植性问题**。
- **问题统计**：高危 1、中危 10、低危 12，全部修复；另修复测试可移植性缺陷 3 类。

## 四、验证结论

- `next lint`：0 error 0 warning；`next build`：编译成功。
- **10/10 集成/契约测试通过**（配对发布基线后端 `nexfab-ai-crm-final/backend`）。
- **重要配对说明**：这份前端与"新计划交接后端"（17/17 模块的 V2 主线）并非同源——交接后端没有 P3 模块（社媒/外联草稿/Agent 库/导入模板/运维状态/分析报表/ai-queue）。若把该前端接到交接后端，上述模块会 404。这是两个代码库的真实分叉，属产品层面待决策项（见总报告），不是本次修复能消解的。

## 五、遗留与建议

1. **前端↔后端配对决策（需产品确认）**：以发布基线前后端为准发布，还是以交接后端为准补 P3 模块/裁剪前端导航。二者接口已分叉（登录参数、auth-login 逻辑也不同）。
2. CSP 可在 HTTPS 部署后从 `frame-ancestors 'none'` report-only 起步逐步收紧。
3. `@next/swc` 原生二进制在本副本曾损坏（npm 缓存问题），已重装修复；如复现，删除 `node_modules/@next/swc-darwin-arm64` 重装即可（Next 会自动回退 wasm，仅构建变慢）。
