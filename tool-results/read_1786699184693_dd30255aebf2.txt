   105→## Bug修复
   106→
   107→### Bug 1: 客户/询盘详情API 500错误 ✅
   108→- **根因**: `/api/customers/[id]` 和 `/api/inquiries/[id]` 的 Prisma `include` 中引用了 `activities` 关系，但 Activity 模型使用多态 `entityType`+`entityId` 模式，没有直接关系
   109→- **修复**: 
   110→  - 从 include 中移除 `activities`
   111→  - 在获取主数据后，用 `db.activity.findMany({ where: { entityType: 'customer'|'inquiry', entityId: id } })` 单独查询
   112→  - 将 activities 数组合并到响应数据中
   113→  - 客户API额外添加了 `samples` 到 include
   114→- **额外修复**: `/api/inquiries` 列表API的 `_count` 中也错误包含了 `activities`，已修复
   115→
   116→### Bug 2: 客户列表公司名重复显示 ✅
   117→- **根因**: 种子数据中部分客户的 `companyName` 和 `companyNameEn` 相同，导致列表中重复显示
   118→- **修复**: `customer-list-view.tsx` 中增加条件判断，仅在 `companyNameEn !== companyName` 时显示英文名
   119→
   120→### Bug 3: 客户详情抽屉来源显示原始英文 ✅
   121→- **根因**: 直接渲染 `customer.source` 字段（如 "exhibition"），未使用中文标签映射
   122→- **修复**: 导入 `INQUIRY_SOURCE_LABELS`，使用 `INQUIRY_SOURCE_LABELS[customer.source]` 显示中文
