# NexFab AI CRM 外贸智能客户管理系统

NexFab AI CRM 是一套面向外贸企业的智能客户管理系统。系统围绕外贸业务真实链路设计，从客户线索、询盘、商机、报价、样品、订单，到单证、物流、收款、数据分析和售后复购，目标是把分散在表格、聊天记录、邮件和人工跟进中的业务过程沉淀为可追踪、可审计、可分析的经营数据。

这个项目的原始 V1.0 思路不是“再做一个客户资料表”，而是为单一外贸公司打造一套 AI 驱动的业务操作系统：**用 AI 把外贸业务员从重复劳动中解放出来，让一个人干三个人的活。**

本仓库是基于 V4.1 总体规划持续优化后的发布快照，重点补齐了外贸 CRM 中最容易断裂的几个环节：

- 线索、客户、询盘、商机、报价、订单之间的数据闭环。
- 销售跟进、样品、合同订单、收款和活动记录之间的过程闭环。
- 数据大屏、客户地图、数据分析和工作台之间的管理闭环。
- AI 助手、AI 分析、AI 草稿和人工审核之间的边界闭环。
- 角色权限、基础审计、状态流转和业务校验之间的安全闭环。

> 重要说明：本项目中的 AI 能力不是免费内置服务。AI 对话、客户洞察、回复草拟、价格建议、市场分析等功能需要接入第三方大模型服务，并由使用方自行承担 API 调用费用。没有配置有效的付费 AI 服务和 API Key 时，AI 功能无法保证可用。

## 这不是传统 CRM：传统 CRM 与 AI CRM 的核心区别

传统 CRM 的核心价值是“记录”和“管理”：记录客户是谁、什么时候联系过、报价多少钱、订单到哪一步。它解决的是信息沉淀、流程规范和团队协作问题。

NexFab AI CRM 的目标是在传统 CRM 之上继续往前走一步：不仅记录发生了什么，还要辅助判断下一步应该做什么，帮助业务员更快回复客户、更快识别机会、更快发现风险、更快形成报价和跟进动作。

换句话说：

- 传统 CRM 像一本结构化客户台账。
- AI CRM 像一个懂外贸流程的业务副手。
- 传统 CRM 让管理者知道“业务员做了什么”。
- AI CRM 进一步帮助业务员判断“接下来怎么做更好”。

### 一句话区别

| 类型 | 核心问题 | 系统主要动作 | 对业务员的帮助 |
| --- | --- | --- | --- |
| 传统 CRM | 客户信息如何保存、查询、分配和统计 | 录入、编辑、筛选、看板、报表 | 少漏客户，方便管理 |
| NexFab AI CRM | 外贸业务如何更快判断、更快响应、更少出错 | 分析、草拟、提醒、评分、建议、校验、预测 | 少做重复劳动，提高成交效率 |

### 详细对比

| 维度 | 传统 CRM | NexFab AI CRM |
| --- | --- | --- |
| 客户档案 | 记录公司名、联系人、电话、邮箱、国家和备注 | 在客户资料基础上沉淀客户画像、客户等级、AI 评分、历史询盘、报价、订单和跟进上下文 |
| 询盘处理 | 人工阅读询盘，手动判断产品、数量、紧急程度和回复方式 | AI 可辅助翻译、总结、分类、识别意图、生成回复草稿，业务员审核后再发送 |
| 报价管理 | 业务员手动查历史价、算成本、写报价 | AI 可参考历史价格、客户等级、市场情况和利润要求给出报价建议，系统保留人工确认边界 |
| 跟进管理 | 记录跟进时间和备注，到期提醒通常依赖人工维护 | 系统沉淀跟进时间线，并可基于沉默客户、逾期动作、商机阶段提醒下一步 |
| 商机推进 | 只记录销售阶段，更多依赖销售经验判断 | 将询盘、客户、跟进、报价、订单串联，让机会从发现到成交可追踪、可复盘 |
| 单证处理 | 人工复制订单信息制作 CI、PL、PI、SC 等文件 | AI 和模板可生成单证草稿，系统提示缺失字段，正式审核和发送必须由人确认 |
| 订单风险 | 订单状态由人工推进，资料不齐时也可能被误改状态 | 通过订单里程碑校验，让发货、完成等关键状态依赖单证、物流和回款条件 |
| 数据分析 | 展示已发生的数据，例如客户数、订单额、回款额 | 在统计基础上辅助识别风险、客户价值、区域机会、销售漏斗和经营异常 |
| 知识沉淀 | 资料分散在业务员个人电脑和聊天记录中 | 产品资料、历史报价、客户反馈和跟进记录可成为 AI 分析和回复草稿的上下文 |
| 管理方式 | 管理者事后看报表 | 管理者可通过数据大屏、客户地图、风险提醒和业务闭环实时看状态 |

### AI CRM 不等于全自动 CRM

NexFab AI CRM 的设计原则不是让 AI 直接替人做决定，而是让 AI 先把重复、低价值、耗时间的工作变成草稿和建议，再由业务员确认。

AI 可以做：

- 把外语询盘翻译成中文摘要。
- 从客户邮件里提取产品、数量、交期、目的港等关键信息。
- 给客户回复邮件生成第一版草稿。
- 根据历史价格和产品信息给出报价参考。
- 根据客户跟进历史生成客户画像。
- 根据订单、物流、收款状态提示风险。
- 根据数据看板解释经营变化。

AI 不应该直接做：

- 自动发送正式报价。
- 自动承诺交期。
- 自动确认订单。
- 自动批准低毛利报价。
- 自动把单证标记为已审核。
- 自动把缺资料订单推进到发货或完成。
- 自动替代财务确认收款。

这也是本项目区别于“接一个聊天机器人”的关键点：AI 被嵌入外贸业务流程，但保留人工确认、审计和状态校验边界。

### 对外贸公司的实际价值

NexFab AI CRM 希望解决的是外贸公司每天反复发生的具体问题：

1. 新询盘太多，业务员来不及逐封精读。
2. 老客户历史报价和沟通记录难找。
3. 新业务员不知道怎么写专业英文回复。
4. 报价容易漏算成本、汇率、毛利和历史价格。
5. 客户很久没跟进，没人提醒。
6. 订单到了发货节点，单证、物流或收款资料却没齐。
7. 管理层只看到结果，不知道过程风险在哪里。
8. 产品知识、术语、历史邮件和客户偏好没有沉淀。

传统 CRM 主要让这些问题“可记录”；NexFab AI CRM 希望让这些问题“可辅助判断、可提前提醒、可形成动作”。

## 项目定位

传统外贸业务常见的问题包括：

1. 客户资料分散在 Excel、微信、邮箱、WhatsApp 和业务员个人电脑里。
2. 询盘、报价、样品、订单之间没有明确关联，后续复盘困难。
3. 报价是否过期、毛利是否合理、订单是否可发货，往往依赖人工经验判断。
4. 单证、物流、收款和售后信息分散，管理层无法快速看到真实风险。
5. AI 工具可以辅助写邮件和做分析，但如果没有人工审核边界，容易把草稿当成正式业务动作。

NexFab AI CRM 的设计目标是把这些问题收拢成一个系统：

- 一线销售可以快速录入客户、询盘、报价、订单和跟进。
- 销售主管可以查看团队漏斗、客户价值、报价状态和订单推进。
- 管理层可以通过数据大屏、分析看板和客户地图查看经营态势。
- 财务可以跟踪应收、已收、逾期和收款状态。
- AI 可以辅助分析、草拟、翻译和建议，但最终业务动作必须由人确认。


## 功能总览

### 1. 工作台

工作台面向日常使用，提供当前业务状态的快速入口：

- KPI 卡片：客户、询盘、报价、订单、收款等关键指标。
- 风险提醒：逾期跟进、未收款、订单状态异常等。
- 快速操作：新建客户、新建询盘、新建报价、打开 AI 助手。
- 趋势图表：业务走势、阶段分布、收入和订单变化。
- 角色差异化：不同角色看到的重点信息不同。

### 2. 客户管理

客户档案是外贸业务的数据中心，承载客户基本信息、联系人、跟进、询盘、报价、订单和活动记录。

主要能力：

- 客户列表、搜索、筛选和详情抽屉。
- 客户级别管理：A/B/C/D 客户分层。
- 国家、城市、行业、来源、负责人等字段管理。
- 联系人维护：姓名、职位、邮箱、电话、WhatsApp、决策人标记。
- 客户跟进记录和活动沉淀。
- 客户看板视图，用于按状态或等级快速查看客户池。

### 3. 客户地图

客户地图用于从国家和区域维度查看市场覆盖情况。

主要能力：

- 按国家统计客户数量。
- 按区域汇总客户和营收。
- 展示国家排行榜、区域营收分布、客户级别分布。
- 通过可视化卡片快速判断市场集中度和空白区域。
- 帮助管理层制定区域拓展策略。

### 4. 询盘管理

询盘模块用于承接客户需求，并作为后续商机和报价的起点。

主要能力：

- 询盘列表、详情、创建和编辑。
- 询盘状态管理。
- 来源记录：邮件、官网、WhatsApp、展会、B2B 平台、LinkedIn、社媒等。
- 优先级管理。
- 与客户、联系人和后续报价关联。
- 询盘看板，支持拖拽或状态化管理。

### 5. 商机管理

商机模块用于补齐“询盘到报价”之间的销售机会承载层。

主要能力：

- 商机阶段管理。
- 商机金额、概率和预计成交日。
- 商机关联客户和询盘。
- 商机详情抽屉。
- 商机跟进时间线。
- 从商机发起报价。
- 报价转订单后可沉淀成交节点。

### 6. 报价管理

报价管理覆盖报价创建、明细、状态流转和后续转订单。

主要能力：

- 报价列表、报价详情、报价看板。
- 报价明细项管理。
- 报价金额、币种、有效期、状态。
- 报价关联客户、询盘和商机。
- 已接受报价转订单。
- 报价状态机和重复转单拦截。
- 报价详情抽屉展示报价、客户、明细和操作。

### 7. 样品管理

样品模块用于记录外贸打样、寄样和测试过程。

主要能力：

- 样品列表和详情抽屉。
- 样品编号、客户、询盘、产品和状态。
- 申请、准备、寄出、签收、测试、通过、失败等状态记录。
- 关联客户和询盘。
- 为后续成交和复盘提供依据。

### 8. 合同订单

订单模块承接报价成交后的正式履约过程。

主要能力：

- 订单列表、订单详情、订单看板。
- 订单编号、客户、报价、金额、币种、状态。
- 订单明细快照。
- 订单状态推进。
- 订单与收款、单证、物流的关联。
- 订单看板和详情抽屉。

V4.1 优化路线中，订单是系统的核心闭环节点。后续版本围绕订单补齐了订单明细冻结、财务同步、单证生成、物流校验和里程碑硬校验。

### 9. 收款管理

收款模块用于记录订单回款、待收和逾期情况。

主要能力：

- 收款列表。
- 收款金额、方式、状态和付款时间。
- 关联订单和客户。
- 已收、待收、逾期统计。
- 收款表单和收款看板。
- 与订单已收金额联动。

### 10. 数据分析

数据分析模块用于管理层和业务负责人查看经营数据。

主要能力：

- 收入、订单、客户、询盘等 KPI。
- 销售趋势。
- 来源分析。
- 客户级别分布。
- 产品、区域、团队等维度分析。
- 图表化经营看板。

### 11. 数据大屏

数据大屏是面向管理层的沉浸式全屏看板。

主要能力：

- 总营收、活跃客户、询盘、订单、转化率、收款率等 KPI。
- 销售漏斗。
- 来源分布。
- 客户级别分布。
- 营收趋势。
- 区域 Top 数据。
- 订单状态分布。
- 团队排行。
- 风险预警。
- 自动刷新和实时显示。

### 12. 社媒运营

社媒运营模块用于管理外贸企业的内容营销和社媒触达。

主要能力：

- 社媒帖子管理。
- 平台支持：LinkedIn、Facebook、Twitter、Instagram、阿里巴巴。
- 内容状态：草稿、已排期、已发布、发布失败。
- 发布日历。
- 互动数据统计：点赞、评论、分享、点击。
- 关联客户和产品。
- 社媒内容分析。

> 当前模块更偏向内容管理和运营记录。真正调用 LinkedIn、Facebook、Instagram、阿里国际站等平台官方 API 发布内容，需要额外的平台开发者账号、API 权限和付费/审核能力。

### 13. 权限中心

权限中心用于管理用户和角色。

主要能力：

- 用户列表。
- 用户新增、编辑、启用和禁用。
- 角色设置。
- 基础权限可视化。
- 管理层、销售主管、销售、财务等角色区分。

### 14. 系统设置

系统设置用于管理当前用户、偏好和系统信息。

主要能力：

- 当前用户信息展示。
- 界面偏好。
- 系统版本和技术栈说明。
- 基础配置入口。

### 15. 活动记录

活动记录用于沉淀业务过程和操作痕迹。

主要能力：

- 客户、询盘、报价、订单等对象的活动记录。
- 跟进、邮件、电话、会议、备注、系统事件。
- 时间线展示。
- 为后续 AI 分析、客户画像和管理复盘提供基础数据。

## AI 功能说明：付费能力，需用户自备服务

本系统名称中包含 “AI”，但仓库不会提供任何免费的商业大模型额度，也不会内置可公开使用的 API Key。

### AI 功能覆盖范围

当前系统中的 AI 能力主要包括：

- AI 助手对话。
- 客户分析和客户洞察。
- 询盘内容理解和回复草拟。
- 商务邮件翻译和润色。
- 报价建议和谈判策略建议。
- 市场研究和目标市场分析。
- 社媒内容创作建议。
- 经营数据解读辅助。

### AI 的业务边界

按照 V4.1 规划原则，AI 是辅助工具，不是业务决策者。

AI 输出应当被视为：

- 建议。
- 草稿。
- 分析参考。
- 风险提示。
- 初步分类。

AI 输出不应被直接视为：

- 正式报价。
- 正式合同。
- 已确认订单。
- 已审核单证。
- 已批准的财务动作。
- 可直接发送给客户的最终文本。

涉及报价、订单、单证、客户敏感信息、财务收款和正式对外发送内容时，必须由业务人员人工确认。

### AI 费用说明

AI 能力需要接入第三方大模型服务，例如：

- OpenAI
- Moonshot / Kimi
- DeepSeek
- 通义千问 / 阿里百炼
- 智谱 AI
- 其他 OpenAI 兼容接口服务

这些服务通常按照模型、输入 token、输出 token、上下文长度、并发量或套餐额度收费。费用由系统使用方自行承担。

请特别注意：

1. 本仓库不包含可用的商业 API Key。
2. 本仓库不承诺任何第三方 AI 服务免费可用。
3. AI 服务的价格、可用性、模型效果和地区访问能力以服务商实际规则为准。
4. 生产环境必须把 API Key 放在服务器环境变量或安全密钥管理系统中。
5. 严禁把真实 API Key 提交到 GitHub。

## 本地启动

### 1. 安装依赖

推荐使用 pnpm：

```bash
pnpm install
```

如果使用 bun，也可以根据本机环境安装依赖，但当前脚本主要以 `pnpm` 和 `prisma` 命令为主。

### 2. 配置环境变量

创建本地 `.env` 文件：

```bash
DATABASE_URL="file:./db/custom.db"
```

如果需要 AI 功能，请额外配置付费 AI 服务的 Key：

```bash
AI_PROVIDER=your-provider
AI_BASE_URL=https://your-provider-compatible-endpoint/v1
AI_MODEL=your-model
AI_API_KEY=your-paid-api-key
```

不要把 `.env` 提交到仓库。

### 3. 初始化数据库

```bash
pnpm prisma generate
pnpm prisma db push
```

如需演示数据，可以执行种子脚本。具体脚本会随版本变化，请先查看 `prisma/` 目录和 `package.json`。

### 4. 启动开发服务

```bash
pnpm dev
```

默认访问：

```text
http://localhost:3000
```
