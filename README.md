# NexFab AI CRM 外贸智能客户管理系统

NexFab AI CRM 是一套面向外贸企业的智能客户管理系统。系统围绕外贸业务真实链路设计，从客户线索、询盘、商机、报价、样品、订单，到单证、物流、收款、数据分析和售后复购，目标是把分散在表格、聊天记录、邮件和人工跟进中的业务过程沉淀为可追踪、可审计、可分析的经营数据。

这个项目的原始 V1.0 思路不是“再做一个客户资料表”，而是为单一外贸公司打造一套 AI 驱动的业务操作系统：**用 AI 把外贸业务员从重复劳动中解放出来，让一个人干三个人的活。**

本仓库是基于 V4.1 总体规划持续优化后的发布快照，重点补齐了外贸 CRM 中最容易断裂的几个环节：

- 线索、客户、询盘、商机、报价、订单之间的数据闭环。
- 销售跟进、样品、合同订单、收款和活动记录之间的过程闭环。
- 数据大屏、客户地图、数据分析和工作台之间的管理闭环。
- AI 助手、AI 分析、AI 草稿和人工审核之间的边界闭环。
- 角色权限、基础审计、状态流转和业务校验之间的安全闭环。

> 重要说明：本项目中的 AI 能力不是免费内置服务。AI 对话、客户洞察、回复草拟、价格建议、市场分析等功能需要接入第三方大模型服务，并由使用方自行承担 API 调用费用。没有配置有效的付费 AI 服务和 API Key 时，AI 功能无法保证可用。

## 这不是传统 CRM：传统 CRM 与 AI CRM 的核心区别

传统 CRM 的核心价值是“记录”和“管理”：记录客户是谁、什么时候联系过、报价多少钱、订单到哪一步。它解决的是信息沉淀、流程规范和团队协作问题。

NexFab AI CRM 的目标是在传统 CRM 之上继续往前走一步：不仅记录发生了什么，还要辅助判断下一步应该做什么，帮助业务员更快回复客户、更快识别机会、更快发现风险、更快形成报价和跟进动作。

换句话说：

- 传统 CRM 像一本结构化客户台账。
- AI CRM 像一个懂外贸流程的业务副手。
- 传统 CRM 让管理者知道“业务员做了什么”。
- AI CRM 进一步帮助业务员判断“接下来怎么做更好”。

### 一句话区别

| 类型 | 核心问题 | 系统主要动作 | 对业务员的帮助 |
| --- | --- | --- | --- |
| 传统 CRM | 客户信息如何保存、查询、分配和统计 | 录入、编辑、筛选、看板、报表 | 少漏客户，方便管理 |
| NexFab AI CRM | 外贸业务如何更快判断、更快响应、更少出错 | 分析、草拟、提醒、评分、建议、校验、预测 | 少做重复劳动，提高成交效率 |

### 详细对比

| 维度 | 传统 CRM | NexFab AI CRM |
| --- | --- | --- |
| 客户档案 | 记录公司名、联系人、电话、邮箱、国家和备注 | 在客户资料基础上沉淀客户画像、客户等级、AI 评分、历史询盘、报价、订单和跟进上下文 |
| 询盘处理 | 人工阅读询盘，手动判断产品、数量、紧急程度和回复方式 | AI 可辅助翻译、总结、分类、识别意图、生成回复草稿，业务员审核后再发送 |
| 报价管理 | 业务员手动查历史价、算成本、写报价 | AI 可参考历史价格、客户等级、市场情况和利润要求给出报价建议，系统保留人工确认边界 |
| 跟进管理 | 记录跟进时间和备注，到期提醒通常依赖人工维护 | 系统沉淀跟进时间线，并可基于沉默客户、逾期动作、商机阶段提醒下一步 |
| 商机推进 | 只记录销售阶段，更多依赖销售经验判断 | 将询盘、客户、跟进、报价、订单串联，让机会从发现到成交可追踪、可复盘 |
| 单证处理 | 人工复制订单信息制作 CI、PL、PI、SC 等文件 | AI 和模板可生成单证草稿，系统提示缺失字段，正式审核和发送必须由人确认 |
| 订单风险 | 订单状态由人工推进，资料不齐时也可能被误改状态 | 通过订单里程碑校验，让发货、完成等关键状态依赖单证、物流和回款条件 |
| 数据分析 | 展示已发生的数据，例如客户数、订单额、回款额 | 在统计基础上辅助识别风险、客户价值、区域机会、销售漏斗和经营异常 |
| 知识沉淀 | 资料分散在业务员个人电脑和聊天记录中 | 产品资料、历史报价、客户反馈和跟进记录可成为 AI 分析和回复草稿的上下文 |
| 管理方式 | 管理者事后看报表 | 管理者可通过数据大屏、客户地图、风险提醒和业务闭环实时看状态 |

### AI CRM 不等于全自动 CRM

NexFab AI CRM 的设计原则不是让 AI 直接替人做决定，而是让 AI 先把重复、低价值、耗时间的工作变成草稿和建议，再由业务员确认。

AI 可以做：

- 把外语询盘翻译成中文摘要。
- 从客户邮件里提取产品、数量、交期、目的港等关键信息。
- 给客户回复邮件生成第一版草稿。
- 根据历史价格和产品信息给出报价参考。
- 根据客户跟进历史生成客户画像。
- 根据订单、物流、收款状态提示风险。
- 根据数据看板解释经营变化。

AI 不应该直接做：

- 自动发送正式报价。
- 自动承诺交期。
- 自动确认订单。
- 自动批准低毛利报价。
- 自动把单证标记为已审核。
- 自动把缺资料订单推进到发货或完成。
- 自动替代财务确认收款。

这也是本项目区别于“接一个聊天机器人”的关键点：AI 被嵌入外贸业务流程，但保留人工确认、审计和状态校验边界。

### 对外贸公司的实际价值

NexFab AI CRM 希望解决的是外贸公司每天反复发生的具体问题：

1. 新询盘太多，业务员来不及逐封精读。
2. 老客户历史报价和沟通记录难找。
3. 新业务员不知道怎么写专业英文回复。
4. 报价容易漏算成本、汇率、毛利和历史价格。
5. 客户很久没跟进，没人提醒。
6. 订单到了发货节点，单证、物流或收款资料却没齐。
7. 管理层只看到结果，不知道过程风险在哪里。
8. 产品知识、术语、历史邮件和客户偏好没有沉淀。

传统 CRM 主要让这些问题“可记录”；NexFab AI CRM 希望让这些问题“可辅助判断、可提前提醒、可形成动作”。

## OPC 一人公司 / 超级个体：为什么外贸更需要 AI CRM

2026 年以来，OPC（One Person Company，一人公司）和“超级个体”成为 AI 创业语境里的高频词。它不是传统意义上只由一个自然人注册的公司，而是指一个核心经营者借助 AI、大模型、自动化工具、SaaS 系统和外包协作，把过去需要一个小团队完成的商业链路压缩到一个人或极小团队手里。

对外贸行业来说，OPC 的吸引力尤其明显：

- 外贸公司天然跨语言、跨时区、跨平台，重复沟通和资料整理非常多。
- 很多中小外贸团队没有专职数据分析、单证、运营、客服和市场研究岗位。
- 一个业务员往往同时承担开发客户、回复询盘、报价、跟单、催款、维护老客户等多种职责。
- AI 工具可以补齐语言、文案、分析、整理、草拟、提醒和自动化能力，让小团队具备更接近大公司的执行能力。

NexFab AI CRM 正是按这个方向设计：它不是给大企业堆复杂流程，而是让一个外贸老板、一个业务负责人，或者一个小型外贸团队，拥有一套“AI 业务中台”。

### 传统外贸公司 vs OPC 型外贸公司

| 维度 | 传统外贸公司 | OPC / 超级个体型外贸公司 |
| --- | --- | --- |
| 组织结构 | 销售、跟单、单证、运营、主管分工较细 | 一个人或少数人主导，AI 和工具承担大量执行工作 |
| 客户开发 | 业务员手动找客户、手动记录、手动跟进 | AI 辅助整理线索、生成开发信、标记高价值客户 |
| 询盘回复 | 人工阅读、翻译、判断、写邮件 | AI 先翻译、摘要、识别需求、生成回复草稿 |
| 报价准备 | 手动查产品、历史报价、成本和利润 | 系统沉淀历史报价，AI 辅助给出价格和谈判建议 |
| 内容运营 | 依赖兼职运营或临时发帖 | 社媒运营模块沉淀内容计划、排期和互动数据，AI 辅助生成内容 |
| 跟进节奏 | 靠业务员记忆和表格提醒 | 系统记录时间线，AI 辅助发现沉默客户和下一步动作 |
| 管理复盘 | 月底做表、手动统计 | 数据大屏、客户地图、分析看板实时呈现 |
| 能力边界 | 一个人只能做自己擅长的事 | AI 补齐语言、文案、分析、资料整理和流程提醒短板 |

### NexFab AI CRM 在 OPC 场景里的角色

如果把 OPC 外贸公司理解为“一个人 + 一组 AI 数字员工 + 一套业务系统”，那么 NexFab AI CRM 承担的是业务系统和 AI 协同中枢：

1. **客户中枢**：所有客户、联系人、国家、等级、来源、历史行为统一沉淀。
2. **销售中枢**：询盘、商机、跟进、报价、订单形成连续链路。
3. **知识中枢**：产品、历史报价、沟通记录、客户偏好成为 AI 可参考的上下文。
4. **执行中枢**：新建客户、跟进客户、生成回复、准备报价、排期社媒内容都在系统里完成。
5. **风控中枢**：订单状态、收款、单证、物流不再只靠人脑记忆，而是通过系统校验和提醒。
6. **管理中枢**：一个人也能通过大屏、地图和报表查看客户分布、业务漏斗和现金流风险。

### OPC 元素在系统中的体现

NexFab AI CRM 已经包含多个符合 OPC 方向的设计元素：

- **AI 助手**：像随身业务助理一样，随时做客户分析、回复草稿、翻译和市场建议。
- **客户画像**：把客户等级、国家、行业、历史询盘、报价和订单组合成可复盘资产。
- **社媒运营**：适合一人公司做轻量内容营销，而不是依赖完整市场部。
- **数据大屏**：让小团队也能拥有管理驾驶舱。
- **客户地图**：快速判断外贸市场覆盖、重点区域和空白国家。
- **统一跟进记录**：让一个人服务大量客户时不丢线索、不忘动作。
- **报价/订单/收款闭环**：减少靠记忆推进流程造成的漏项。
- **AI 人工确认边界**：AI 是数字员工，但老板或业务员仍然是最终负责人。

### 为什么 README 要强调 OPC

因为 NexFab AI CRM 的价值不只是“一个系统多几个 AI 按钮”，而是顺应 OPC 和超级个体趋势，把外贸公司的组织能力压缩进软件和 AI 工作流里。

对一个小外贸团队来说，这套系统希望达到的效果是：

- 少招一个重复录入岗位。
- 少花大量时间翻译和写第一版邮件。
- 少因为客户太多而忘记跟进。
- 少因为报价和订单资料分散而出错。
- 少依赖老板每天追问业务员进度。
- 让一个强业务员能管理更多客户、更多国家、更多商机。

这和原始 V1.0 的目标是一致的：**不是为了把 CRM 做得更复杂，而是为了让小团队和超级个体具备更强的外贸执行力。**

## 项目定位

传统外贸业务常见的问题包括：

1. 客户资料分散在 Excel、微信、邮箱、WhatsApp 和业务员个人电脑里。
2. 询盘、报价、样品、订单之间没有明确关联，后续复盘困难。
3. 报价是否过期、毛利是否合理、订单是否可发货，往往依赖人工经验判断。
4. 单证、物流、收款和售后信息分散，管理层无法快速看到真实风险。
5. AI 工具可以辅助写邮件和做分析，但如果没有人工审核边界，容易把草稿当成正式业务动作。

NexFab AI CRM 的设计目标是把这些问题收拢成一个系统：

- 一线销售可以快速录入客户、询盘、报价、订单和跟进。
- 销售主管可以查看团队漏斗、客户价值、报价状态和订单推进。
- 管理层可以通过数据大屏、分析看板和客户地图查看经营态势。
- 财务可以跟踪应收、已收、逾期和收款状态。
- AI 可以辅助分析、草拟、翻译和建议，但最终业务动作必须由人确认。

## 核心业务链路

系统按外贸业务从获客到复购的主链路组织：

```text
线索 / 社媒互动
  -> 客户档案
  -> 询盘
  -> 商机
  -> 跟进记录
  -> 报价
  -> 样品
  -> 合同订单
  -> 单证
  -> 物流 / 发货
  -> 收款
  -> 售后 / 复购
```

在当前发布快照中，前台已经实现的主要模块包括：

- 工作台
- 目标线索
- 客户档案
- 客户地图
- 产品资料库
- 报价管理
- 样品管理
- 合同订单
- 收款管理
- 数据分析
- 数据大屏
- 社媒运营
- 权限中心
- 系统设置
- 活动记录
- AI 助手

其中，`客户地图`、`数据大屏`、`社媒运营` 是在 V4.1 后续优化阶段补充的管理和获客增强模块。

## 功能总览

### 1. 工作台

工作台面向日常使用，提供当前业务状态的快速入口：

- KPI 卡片：客户、询盘、报价、订单、收款等关键指标。
- 风险提醒：逾期跟进、未收款、订单状态异常等。
- 快速操作：新建客户、新建询盘、新建报价、打开 AI 助手。
- 趋势图表：业务走势、阶段分布、收入和订单变化。
- 角色差异化：不同角色看到的重点信息不同。

### 2. 客户管理

客户档案是外贸业务的数据中心，承载客户基本信息、联系人、跟进、询盘、报价、订单和活动记录。

主要能力：

- 客户列表、搜索、筛选和详情抽屉。
- 客户级别管理：A/B/C/D 客户分层。
- 国家、城市、行业、来源、负责人等字段管理。
- 联系人维护：姓名、职位、邮箱、电话、WhatsApp、决策人标记。
- 客户跟进记录和活动沉淀。
- 客户看板视图，用于按状态或等级快速查看客户池。

### 3. 客户地图

客户地图用于从国家和区域维度查看市场覆盖情况。

主要能力：

- 按国家统计客户数量。
- 按区域汇总客户和营收。
- 展示国家排行榜、区域营收分布、客户级别分布。
- 通过可视化卡片快速判断市场集中度和空白区域。
- 帮助管理层制定区域拓展策略。

### 4. 询盘管理

询盘模块用于承接客户需求，并作为后续商机和报价的起点。

主要能力：

- 询盘列表、详情、创建和编辑。
- 询盘状态管理。
- 来源记录：邮件、官网、WhatsApp、展会、B2B 平台、LinkedIn、社媒等。
- 优先级管理。
- 与客户、联系人和后续报价关联。
- 询盘看板，支持拖拽或状态化管理。

### 5. 商机管理

商机模块用于补齐“询盘到报价”之间的销售机会承载层。

主要能力：

- 商机阶段管理。
- 商机金额、概率和预计成交日。
- 商机关联客户和询盘。
- 商机详情抽屉。
- 商机跟进时间线。
- 从商机发起报价。
- 报价转订单后可沉淀成交节点。

### 6. 报价管理

报价管理覆盖报价创建、明细、状态流转和后续转订单。

主要能力：

- 报价列表、报价详情、报价看板。
- 报价明细项管理。
- 报价金额、币种、有效期、状态。
- 报价关联客户、询盘和商机。
- 已接受报价转订单。
- 报价状态机和重复转单拦截。
- 报价详情抽屉展示报价、客户、明细和操作。

### 7. 样品管理

样品模块用于记录外贸打样、寄样和测试过程。

主要能力：

- 样品列表和详情抽屉。
- 样品编号、客户、询盘、产品和状态。
- 申请、准备、寄出、签收、测试、通过、失败等状态记录。
- 关联客户和询盘。
- 为后续成交和复盘提供依据。

### 8. 合同订单

订单模块承接报价成交后的正式履约过程。

主要能力：

- 订单列表、订单详情、订单看板。
- 订单编号、客户、报价、金额、币种、状态。
- 订单明细快照。
- 订单状态推进。

## AI 功能说明：付费能力，需用户自备服务

本系统名称中包含 “AI”，但仓库不会提供任何免费的商业大模型额度，也不会内置可公开使用的 API Key。

### AI 功能覆盖范围

当前系统中的 AI 能力主要包括：

- AI 助手对话。
- 客户分析和客户洞察。
- 询盘内容理解和回复草拟。
- 商务邮件翻译和润色。
- 报价建议和谈判策略建议。
- 市场研究和目标市场分析。
- 社媒内容创作建议。
- 经营数据解读辅助。

### AI 的业务边界

按照 V4.1 规划原则，AI 是辅助工具，不是业务决策者。

AI 输出应当被视为：

- 建议。
- 草稿。
- 分析参考。
- 风险提示。
- 初步分类。

AI 输出不应被直接视为：

- 正式报价。
- 正式合同。
- 已确认订单。
- 已审核单证。
- 已批准的财务动作。
- 可直接发送给客户的最终文本。

涉及报价、订单、单证、客户敏感信息、财务收款和正式对外发送内容时，必须由业务人员人工确认。

### AI 费用说明

AI 能力需要接入第三方大模型服务，例如：

- OpenAI
- Moonshot / Kimi
- DeepSeek
- 通义千问 / 阿里百炼
- 智谱 AI
- 其他 OpenAI 兼容接口服务

这些服务通常按照模型、输入 token、输出 token、上下文长度、并发量或套餐额度收费。费用由系统使用方自行承担。

请特别注意：

1. 本仓库不包含可用的商业 API Key。
2. 本仓库不承诺任何第三方 AI 服务免费可用。
3. AI 服务的价格、可用性、模型效果和地区访问能力以服务商实际规则为准。
4. 生产环境必须把 API Key 放在服务器环境变量或安全密钥管理系统中。
5. 严禁把真实 API Key 提交到 GitHub。

### 建议的 AI 环境变量

不同服务商的变量名可能不同，下面是推荐约定：

```bash
AI_PROVIDER=moonshot
AI_BASE_URL=https://api.moonshot.cn/v1
AI_MODEL=moonshot-v1-8k
AI_API_KEY=your-paid-api-key
```

或使用 OpenAI 兼容命名：

```bash
OPENAI_BASE_URL=https://api.openai.com/v1
OPENAI_MODEL=gpt-4o-mini
OPENAI_API_KEY=your-paid-api-key
```

实际部署时请以当前代码和部署脚本读取的变量为准。如果使用 `z-ai-web-dev-sdk` 或其它代理服务，也需要根据对应服务的要求配置密钥和网络访问。

## 本地启动

### 1. 安装依赖

推荐使用 pnpm：

```bash
pnpm install
```

如果使用 bun，也可以根据本机环境安装依赖，但当前脚本主要以 `pnpm` 和 `prisma` 命令为主。

### 2. 配置环境变量

创建本地 `.env` 文件：

```bash
DATABASE_URL="file:./db/custom.db"
```

如果需要 AI 功能，请额外配置付费 AI 服务的 Key：

```bash
AI_PROVIDER=your-provider
AI_BASE_URL=https://your-provider-compatible-endpoint/v1
AI_MODEL=your-model
AI_API_KEY=your-paid-api-key
```

不要把 `.env` 提交到仓库。

### 3. 初始化数据库

```bash
pnpm prisma generate
pnpm prisma db push
```

如需演示数据，可以执行种子脚本。具体脚本会随版本变化，请先查看 `prisma/` 目录和 `package.json`。

### 4. 启动开发服务

```bash
pnpm dev
```

默认访问：

```text
http://localhost:3000
```

## V4.1 优化路线摘要

### 阶段 2：线上可用性与体验稳定

随后修复空引用、数值类型、上传、PDF、通知、线索、社媒互动等问题，提高真实使用稳定性。

- AI 不能直接修改正式业务数据。
- PII 加密和受控访问。
- 审计日志补齐。

- NL2SQL 和 RAG 使用边界。
- RBAC 和数据范围过滤。
