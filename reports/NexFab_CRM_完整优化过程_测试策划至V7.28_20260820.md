## 一、测试策划与验收基线

本轮优化不是单点功能开发，而是按 V4.1 总体规划和交叉审查报告持续补齐外贸 CRM 的完整闭环。

测试策划基线主要包括：

1. 业务闭环：线索、客户、询盘、商机、报价、订单、生产、物流、单证、收款、售后、复购需要能串起来。
2. 权限闭环：前端隐藏按钮不算安全，所有业务 API 都需要后端认证、RBAC、数据范围过滤。
3. AI 边界：AI 只能生成建议、草稿、分析，不能直接修改正式业务状态；高风险 AI 输出必须人工审核。
4. PII 与审计：客户联系方式、地址等敏感信息需要加密、受控解密、导出审计、权限变更审计。
5. 订单与财务一致性：订单金额、收款、状态、单证、物流必须互相校验，不能只靠人工改状态。
6. 发布门槛：每轮至少检查 `git diff --check`、Prisma 校验、TypeScript 检查、生产构建或线上接口健康。

## 三、优化路线的阶段性逻辑

### 阶段 1：先把业务模块补齐

V5.7 到 V6.3 主要解决“有没有”的问题：导入、日历、样品看板、单证、生产、物流、社媒、报价转订单逐步出现。这个阶段的重点是让外贸 CRM 不再只是客户/询盘/报价列表，而是开始覆盖外贸真实交付链路。

### 阶段 2：把线上问题和基础体验稳定下来

V6.5 到 V7.4 主要处理线上可用性和模块扩展：空引用、报价金额类型、邮件/WhatsApp、PDF、通知、线索管理、社媒互动。这个阶段发现并记录了上传接口移除导致前端上传失效等问题，为后续安全加固做铺垫。

### 阶段 3：把安全、权限、审计变成后端硬约束

V7.5 到 V7.11 是安全主线：AI 不能直接改业务、PII 加密、审计日志、文件安全、NL2SQL 防护、RBAC、状态机、生产预检、PII 解密审计。这个阶段把“前端有按钮控制”升级为“后端 API 兜底控制”。

### 阶段 4：把报价、订单、财务、单证做成闭环

V7.12 到 V7.18 解决核心交易链路：报价过期、低毛利审批、订单 ready 状态口径、收款自动同步、订单明细冻结、历史订单回填、AI 安全、产品外贸字段、财务收款字段和 TypeScript 全量归零。这个阶段开始从“能操作”走向“数据一致、可追溯、可审计”。

### 阶段 5：把销售过程和成交后经营补齐

V7.19 到 V7.28 完成售后复购、AI 审批中心、商机、统一跟进、商机详情、商机到报价、报价到订单、外贸单证、订单里程碑硬校验。到 V7.28，主链路已经形成：

线索/社媒互动 → 客户 → 询盘 → 商机 → 跟进 → 报价 → 订单 → 单证 → 物流 → 收款 → 售后/复购。

## 六、结论

这轮优化过程不是简单堆功能，而是沿着 V4.1 测试策划和交叉审查结果逐层闭环：

- 先补业务模块。
- 再修线上可用性和真实 bug。
- 再建立后端权限、安全、审计、AI 边界。
- 再打通报价、订单、财务、单证。
- 最后把销售跟进、商机、成交、售后和复购串成完整业务链。

截至 V7.28，系统已经从“功能可演示的 CRM”推进到“具备外贸业务闭环、权限边界、AI 审核、财务一致性和订单硬校验的预发布级 CRM”。
